Claude 3.5 Sonnet 发布后，我尝试用它辅助重构了一个遗留系统模块，效果出乎意料。

## 背景

一个三年前的老模块，原始开发者已离职。代码风格不一致，缺乏测试，业务逻辑散落在各处。

## 重构过程

### 1. 理解代码

把 2000 行的核心类贴给 Claude：

```
这是一个订单处理模块，请帮我：
1. 梳理主要业务流程
2. 识别代码坏味道
3. 给出重构建议
```

Claude 输出的分析：

- **职责混乱**：OrderService 同时处理支付、库存、通知
- **重复代码**：状态转换逻辑在 5 处重复
- **硬编码**：大量魔法数字和字符串
- **缺失异常处理**：多个空指针风险

### 2. 生成单元测试

```
为 OrderService 的 cancelOrder 方法生成单元测试，覆盖：
- 正常取消
- 已发货无法取消
- 重复取消
- 并发取消
```

生成的测试用例覆盖了所有边界情况，我只做了少量调整。

### 3. 提取方法

```
把这个 300 行的方法拆分成多个职责单一的小方法
```

重构后每个方法不超过 30 行，逻辑清晰。

### 4. 生成文档

```
为重构后的 OrderService 生成 API 文档
```

## 效果对比

| 指标 | 人工 | AI 辅助 |
|------|------|---------|
| 理解代码 | 4h | 1h |
| 编写测试 | 8h | 2h |
| 重构实现 | 12h | 4h |
| 文档编写 | 2h | 0.5h |
| **总计** | **26h** | **7.5h** |

## 使用技巧

1. **提供上下文**：给足够的背景信息
2. **小步迭代**：一次只让 AI 做一件事
3. **人肉审查**：AI 生成的一定要 Review
4. **保留原代码**：对比 diff 确保逻辑不变

## 局限性

- 对项目特定约定理解不足
- 可能生成过时的 API 用法
- 需要人工验证边界情况
