技术债务不可避免，关键是如何管理。

## 什么是技术债务

就像财务债务：
- 借债（快速实现）→ 获得时间
- 利息（维护成本）→ 持续付出
- 还债（重构）→ 一次性付出

## 分类

| 类型 | 示例 | 紧迫度 |
|------|------|--------|
| 战略性债务 | 为抢占市场临时方案 | 低 |
| 无意债务 | 缺乏经验写出的烂代码 | 中 |
| 增长性债务 | 系统规模增长导致的瓶颈 | 高 |

## 判断标准

何时重构？
- 修改这个模块超过 3 次都踩坑
- 新人看这代码超过 30 分钟还没懂
- 每次改动都引入 bug

何时忍耐？
- 代码即将废弃
- 重构成本 > 收益
- 业务优先级更高

## 策略

1. **记录债务**：在代码注释或 Issue 中标记
2. **量化成本**：估算每次修改的额外时间
3. **制定计划**：在迭代中逐步偿还

```java
// TODO: 技术债务 - 使用策略模式重构，预计 2 天
// 当前方案每次新增支付方式都要改这里

    if ("alipay".equals(type)) {
        // ...
    } else if ("wechat".equals(type)) {
        // ...
    }
}
```
